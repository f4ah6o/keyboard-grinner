# Repository Guidelines

## Project Structure & Module Organization
- `src/keyboard-grinner.py` holds the full layout engine: dataclasses for `RowSpec`, geometry helpers, and an `example_usage()` runner.
- `pyproject.toml` pins Python 3.11+, declares `numpy` and `matplotlib`; `uv.lock` is generated by the uv package manager.
- `README.md` explains the rotation intent in Japanese; update it whenever new layout rules or inputs are added.
- `examples/layout.sample.json` demonstrates a KLE-style `layout_matrix` plus per-row segment definitions consumed by the CLI.

## Build, Test, and Development Commands
- `uv sync` installs dependencies defined in `pyproject.toml` and refreshes `uv.lock`.
- `uv run python src/keyboard-grinner.py` executes the demo pipeline: builds rects, places circles, and opens a Matplotlib preview.
- `uv run python src/keyboard-grinner.py --config examples/layout.sample.json --max-angle 20` uses the JSON input (with optional overrides like `--key-height` or `--row-gap`).

## Configuration & Inputs
- Supply `--config path/to/file.json`. Two styles are supported:
  - Low-level `row_specs`: each entry provides `key_widths`, `segment_lengths`, and optional `repeat` to clone rows.
  - High-level `layout_matrix`: KLE-style arrays like `[{"w":1.25},"A","S",...]`; widths are inferred automatically.
- When using `layout_matrix`, optionally add `segment_lengths` (applied to all rows) or `segment_lengths_per_row` to control the horizontal/arc partitions; omit them to keep entire rows horizontal.
- Command-line overrides (`--max-angle`, `--key-height`, `--row-gap`) take precedence over whichever JSON style you choose.

## Coding Style & Naming Conventions
- Follow PEP 8 with 4-space indents and descriptive snake_case names; reserve CamelCase for dataclasses and enums.
- Type hints are mandatory for public functions; prefer `Literal` and `TypedDict` when they clarify geometry contracts.
- Keep functions single-responsibility (e.g., `build_rects`, `rotate_rectangles`); add concise docstrings explaining math context.

## Testing Guidelines
- Tests are not present yet; create `tests/` and organize specs by feature: `tests/test_geometry.py`, `tests/test_row_specs.py`, etc.
- Use `pytest` with `uv add pytest` and run via `uv run pytest`; add golden-data fixtures for row specs covering edge cases (single wide key, asymmetric rows).
- Target at least smoke coverage for `build_rects`, pivot selection, and gap calculations; assert numeric tolerances using `numpy.testing` helpers.

## Commit & Pull Request Guidelines
- Mirror the existing Git history: short, imperative summaries (`Create keyboard-grinner.py`, `Set up Python project with uv`).
- Each PR should describe the motivation, summarize functional changes, and link relevant issues; attach screenshots or Matplotlib outputs when altering visuals.
- Keep commits focused (setup, feature, docs) and ensure `uv run python src/keyboard-grinner.py` succeeds before requesting review.
